
# 目的
本项目旨在将嵌入式裸机开发中的核心知识点（I2C 通信、DMA 数据转运、非阻塞状态机设计、人机交互）融会贯通，通过一个完整的软硬件结合的实战项目，全面提升底层驱动开发与系统架构能力。

# 核心技术栈
底层开发：C 语言, STM32 HAL 库, STM32CubeMX, Keil MDK
通信协议：I2C (非阻塞 DMA 模式)
硬件外设：OLED 显示屏、按键交互、AHT20 + BMP280 温湿度气压传感器模块

# 功能说明与架构设计
功能实现：实时采集环境温度、湿度与大气压数据，并刷新 OLED 界面；配备按键交互逻辑。
架构设计：采用 I2C + DMA + 非阻塞状态机 架构。彻底摒弃了传统的 HAL_Delay 死等模式，将数据采集与 UI 刷新解耦，大幅提升 CPU 利用率。
硬件选型考量：选用 I2C 接口的 AHT20 温湿度传感器，而非常见的 DHT22 单总线。核心优势在于：单总线协议极易受到系统中断的干扰，以往为了时序稳定甚至需要临时关闭全局中断；而 I2C 配合 DMA，不仅时序稳定、精度更高，且彻底释放了 CPU 的负担。

# 问题解决与经验积累
## 1. DMA 发送死锁与 I2C 物理总线被拉死 (最严重)
现象：程序卡在 DMA 发送状态，死等回调函数；连原本正常的阻塞式 AHT20 读取也宣告失败。
原因分析：AHT20 没有内部寄存器概念。但最初我错误地使用了 HAL_I2C_Mem_Write_DMA()。Mem_ 系列函数专用于带内部寄存器的 I2C 器件，底层会多发一个字节的“寄存器地址”。这个多出来的字节被 AHT20 视为错误指令，AHT20 强行拉低 SDA 线，导致物理 I2C 总线锁死。
排查手段：通过状态机配合串口打印，锁定卡死节点；或使用 Keil 的 Stop 按钮，查看左侧 Call Stack（调用栈）与反汇编窗口，追踪 PC 指针停在哪里。
解决方案：对于没有寄存器的 I2C 设备，必须使用 HAL_I2C_Master_Transmit_DMA() 和 HAL_I2C_Master_Receive_DMA()。
## 2. AHT20 初始化失败
现象：直接发送测量命令失败。
解决方案：AHT20 上电后必须发送特定的复位/初始化指令（同样需使用 Master_Transmit），不能直接发测量命令。
## 3. BMP280 读不出数据
原因排查：查阅数据手册确认地址（BMP280 的器件地址受 SDO 引脚电平影响，为 0x76 或 0x77）；且 BMP280 的原始数据需要按照手册公式进行复杂解析。此外，读取气压前必须先触发一次温度读取作为补偿参数。
## 4. DMA 接收缓冲区出现脏数据 / 硬件错误
根因分析：DMA 搬运数据是直接在外设和内存间进行的，不经过 CPU。如果将接收缓冲数组定义在局部函数的栈（Stack）上，函数执行完毕后栈内存会被释放，DMA 仍在往里搬运垃圾数据，导致内存踩踏甚至触发 HardFault。
解决方案：凡是作为 DMA 目标的接收缓冲区，必须定义为全局变量（Global） 或 static 静态变量。
## 5. 状态机永远卡死，无法进入回调
现象：CubeMX 配置了 DMA，代码里也重写了 HAL_I2C_MemTxCpltCallback 回调，但状态机就是死锁。
根因分析：在 CubeMX 的 NVIC 设置中，忘记勾选 I2C Event interrupt（I2C 事件中断）。硬件 DMA 干完活后，无法触发中断通知 CPU，导致回调函数成了摆设。
解决方案：排查 CubeMX 的 NVIC 配置，补齐底层中断使能。
