
# 目的
把嵌入式裸机开发的一些知识汇集在一起，作为一个锻炼
# 主要内容
项目采用 **I2C+DMA + 非阻塞状态机** 架构进行数据采集，并配备按键交互与 OLED 界面显示。
传感器：AHT20 + BMP280（合成模块，拼夕夕上面有，需要自己手动焊接），选用 I2C 型温湿度 AHT20，规避 DHT22 单总线容易被中断干扰的缺陷，不需要读数据时临时关全局中断，时序稳定、精度更高。
通信：I2C
开发环境：HAL库+STM32CubeMX + Keil5
## 功能说明
采集温度、湿度、气压数据
## 遇到的问题以及解决办法
1.（于我而言最严重）现象：程序卡在DMA发送状态一直没有进入回调，原本用阻塞读取正常AHT20也读取不了
原因：AHT20没有寄存器概念，所以用HAL库的时候不能用HAL_I2C_Mem_Write_DMA()，而是要用HAL_I2C_Master_Transmit_DMA()，`Mem_` 系列函数是专门用于带有内部寄存器的 I2C 器件，
会在底层多发一个字节的寄存器地址，多出来的寄存器地址会被误认为是错误指令导致AHT20强行拉低SDA线，锁死整个物理总线。
解决办法：通过状态机，串口打印状态，锁定程序卡在哪里，或者在 Keil 里按下Stop按钮，看看左侧的 Call Stack（调用栈），或者看反汇编窗口，看 PC 指针停在了哪个函数附近。
感悟：在用传感器的时候要记得看看他们有没有寄存器，没有寄存器的 I2C 器件（如 AHT20、MPU6050 的纯数据流），必须用 HAL_I2C_Master_Transmit_DMA 和 HAL_I2C_Master_Receive_DMA。
然后就是多积累经验。

2.现象：在向AHT20发送测量命令时失败
原因：AHT20上电后必须先复位/初始化不能直接发测量指令，注意：初始化的时候也要用Master_Transmit

3.现象：BMP280读不出数据
解决办法：看一下数据手册或者问ai，BMP在不同情况下slave address是有所改变的，注意看自己的是0X76还是X77也可以用函数试一下看看有没有发送成功，
BMP280数据是需要解析的，数据手册有具体的公式，要先读温度才能读气压。


4.现象：数据缓冲区读到的数据有问题
原因：利用DMA转运数据时要把接收缓冲区的数组定义为全局变量，DMA 搬运数据是直接在内存和 I2C 外设之间进行的，不经过 CPU。如果你把接收缓冲区定义在函数内部的栈上，函数一返回，
那块内存就被释放了，DMA 可能搬进来一堆垃圾数据，甚至触发硬件错误 。


5.现象：CubeMX 配置了 DMA，代码里也写了 `HAL_I2C_MemTxCpltCallback` 回调函数，但状态机永远卡在第一步，死活进不了回调。
原因：cubeMX忘记添加中断 I2C Event interrupt导致不能进回调函数，硬件干完活无法通知 CPU，状态机自然死锁。
